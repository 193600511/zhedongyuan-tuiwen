# 推文质量评分标准（100 分制 · 五维）

> 评价引擎：`scripts/score_article.py` v1.4
> 标定语料：342 篇已发布历史推文（D:/Desktop/推文）+ 3 篇新出稿 + 1 篇故意写坏的反例

## 一、为什么要有评分

体检脚本（`check_article.py`）只回答「有没有违规」，回答不了「这篇好不好」。评分补上后半句：

| | 体检 check_article.py | 评分 score_article.py |
|---|---|---|
| 输出 | 致命 / 建议 / 提示清单 | 0–100 分 + 等级 + 编辑点评 |
| 判定 | 二值（合规/不合规） | 连续（差在哪、差多少） |
| 视角 | 只看格式硬规范 | 格式 + 结构 + 内容 + 体验 + 合规 |
| 用途 | 发布前卡关 | 改稿方向、多篇比稿、沉淀写作标准 |

两者共用同一个解析器，**格式项的判定口径完全一致**，不会出现「体检说过、评分扣分」的分裂。

## 一点五、编辑点评（v1.2 新增）

评分条下面紧跟「编辑点评」：把每条扣分项翻译成编辑口吻的人话，按 **现象 → 为什么 → 怎么改** 三段展开：

- **必须改（❗）**：硬规范与发布风险类——字号/字体/行距不对、落款缺失、占位符、绝对化表述、预告缺时间地点、敏感词。
- **可以更好（💡）**：效果类——信息密度、句长、图文比、首屏吸引力、分节、段落节奏。
- **做得好的（✅）**：客观成立才夸——格式满分、落款齐全且署名正确、分节 ≥2 处、图文比 ≤3、无绝对化。宁缺勿滥，不硬凑彩虹屁。

总评一句话 = 分数等级 + 稿型 + **最短板维度及其内部具体问题** + 分级处置语（A+「顺手改掉就能直发」…D「逐段重写比打补丁快」）。

实现位置：`score_article.py` 内 `critique()` / `_issue_text()`（约 40 条规则，按扣分理由关键词路由到点评文案）；去重逻辑保证同一问题只点评一次。终端输出、`--json`（critique 字段）、HTML 评分卡三处共用同一份点评。

## 二、五维权重

| 维度 | 权重 | 考察什么 | 主要扣分项 |
|---|---|---|---|
| 格式规范 | 30 | 学院硬规范 | 正文字号、font-family、行距、字距、缩进、对齐、图片数 |
| 结构完整 | 20 | 稿子该有的骨头 | 头图、开头装饰块、导语、分节、落款五件套、底部关注图 |
| 内容质量 | 25 | 信息与表达 | 长段、信息密度、绝对化表述、占位符、重复句、稿型关键信息 |
| 阅读体验 | 17 | 移动端可读性 | 图文比、段落数、句长、首屏信息、连续空段 |
| 合规风险 | 8 | 发布风险 | 敏感表述、纯黑文字色 |

> **不计分项（2026-11-05 用户确认）**：外链 / 本地图片属发布流程（发布前统一上传素材库替换），不是内容缺陷，评分不扣、点评不提；体检脚本仍会在发布提醒里列出来。

**权重依据**：格式是学院明文规范（《采编部教程》），权重最高；结构决定「像不像一篇正式推文」；内容与体验决定打开后的完读率；合规是底线但可判定项少（敏感词＋纯黑文字），权重最低。v1.3 把外链移出评分后，合规由 10 降到 8，腾出的 2 分给阅读体验。

## 三、稿型自适应（关键设计）

同一把尺子量所有稿型会误伤——散文被扣「信息密度」、预告被扣「导语不够长」。引擎先判稿型，再选尺子：

| 稿型 | 识别信号 | 专属考察 | 免除项 |
|---|---|---|---|
| 新闻/会议类 | 默认 | 导语 40–300 字带时间锚点、主体引述、信息密度 ≥3 | — |
| 预告/赛事类 | 大赛/赛项/参赛/敬请期待 | 主办方、时间、地点三项齐全 | 短段分行、导语长度、分节、首屏时间锚点 |
| 通知/服务类 | 通知/须知/关于…的通知 | 分条编号、咨询电话、时间 | 导语长度、主体引述 |
| 风景/时节类 | 景物时令词密度 | 画面感词 ≥6/百字、正文 300 字以上 | 信息密度、主体引述、时间锚点 |
| 人物类 | 榜样/匠心/专访 + 第三人称 | 人物引述、具体经历（年份/次数） | 信息密度通用项 |

识别准确率抽检：342 篇存档判定为 新闻 205 / 预告 53 / 通知 47 / 人物 27 / 风景 10，与人工抽样一致。

## 四、等级与处置

| 分数 | 等级 | 含义 | 处置 |
|---|---|---|---|
| ≥90 | A+ | 可直接发布 | 只剩发布操作（传图、确认编辑署名） |
| 84–89 | A | 小修可发 | 修 1–2 处扣分项即可 |
| 76–83 | B | 基本合格 | 按「优先修复」清单优化后发 |
| 68–75 | C | 明显短板 | 结构或格式有硬伤，改完重评 |
| <68 | D | 返工 | 多维度同时失分，建议重写 |

退出码：0 = ≥80 可发；1 = 70–79；2 = <70。

## 五、标定结果（真实数据）

342 篇已发布存档的评分分布：

| 指标 | 数值 |
|---|---|
| 中位数 | 80 |
| P25 / P75 | 77 / 85 |
| P90 | 87 |
| 最低 / 最高 | 63 / 93 |
| 等级分布 | A+ 9 · A 74 · B 188 · C 69 · D 2 |

| 稿件 | 稿型 | 得分 | 主要扣分 |

## 六、用法

```bash
# 终端评分卡
python scripts/score_article.py article.html

# 只取结论（适合批处理）
python scripts/score_article.py article.html --brief
# → A  87/100  小修即可发布  [预告/赛事类]

# 机器可读（含每项扣分明细）
python scripts/score_article.py article.html --json

# 可视化评分卡（HTML，可直接发给同事看）
python scripts/score_article.py article.html --html score.html
```

## 七、设计纪律

1. **只扣可客观判定的事实**：字号、行距、缺项、占位符、外链——有就是有。审美、文风偏好不入分。
2. **位置定位失败不扣分**：头图/底图按「正文段落在原文中的位置」判断，定位不到时放过（宁漏不误杀）。
3. **同一问题只扣一次**：体检已判致命项（如落款缺失）在评分里按维度扣一次，不重复叠加。
4. **权重与阈值有数据支撑**：任何阈值调整后必须重跑 342 篇标定，中位数偏离 80±3 就说明尺子歪了。
